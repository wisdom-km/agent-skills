# 记忆模板（常驻 agent 部件 3/5）

复制到项目里改。原则：**只存查不回来的东西**。别的系统里已经有的，只存指针（链接或 ID）。

## 存在哪

- 记忆是一个文件目录。目录要落到持久存储（数据库或对象存储），不要只放在 worker 本机磁盘：worker 换了、机器重启了，记忆还要在。
- 每个用户一份目录，和收件箱一一对应。
- 记忆里是真实用户数据（[D]）：要有备份和恢复步骤（M-11），不写密钥（M-03）。

## 目录结构

```
memory/<inbox_id>/
  instructions.md        # 用户指令：每次 run 都加载
  notes/
    INDEX.md             # 用户笔记索引：每次 run 都加载
    preferences.md       # 例：偏好
    corrections.md       # 例：用户纠正过的错
  told.md                # 已经告诉过用户的话：每次 run 都加载（或由 worker 加载最近几条消息代替）
  tasks/
    INDEX.md             # 任务索引：每次 run 都加载
    T-3.md               # 每个进行中的任务一份进度文件，用到才读
```

每次 run 固定加载：`instructions.md`、`notes/INDEX.md`、`told.md`、`tasks/INDEX.md`。其他文件用到才读。这部分加上系统提示和工具定义，是每个 run 的固定开销，要尽量小，并开启 prompt caching。

## 每类文件的格式

### instructions.md（用户指令）

```markdown
# 用户指令
- 2026-01-05：工作日早上 8 点（用户时区）发早报；周末不发。
- 2026-01-09：涉及付款的事一律先问我。
```

用户说过的、关于 agent 行为的话，原样记下，带日期。用户不在场时，agent 靠它做决定。

### notes/INDEX.md（用户笔记索引）

```markdown
# 用户笔记索引
- preferences.md：沟通偏好（中文、要结论先行）
- corrections.md：纠正过的 3 处错误，最近一次 2026-01-12
```

一开始一个文件就够；变长了再拆成小文件，索引每行一句说清里面有什么。

### told.md（已经告诉过用户的话）

```markdown
# 已告知
- 2026-01-12 08:00 早报：A 项目延期到周五（来源：tracker#123）
- 2026-01-12 15:20 跟进：已提醒对方回复报价单
```

只记要点和时间，用来避免重复说同一件事。发件箱发成功后追加一行。

### tasks/INDEX.md 和 tasks/T-x.md（任务进度）

```markdown
# 任务索引
- T-3 等供应商回复报价 · 进行中 · 下次检查 2026-01-14（定时器 tmr_7）
- T-4 每周整理周报 · 周期任务 · 定时器 tmr_2
```

```markdown
# T-3 等供应商回复报价
- 指针：邮件线程 <链接或 ID>；工单 tracker#123
- 已完成：2026-01-12 发出询价；已提醒一次
- 还剩：对方回复后对比价格，请用户确认
- 下一步：2026-01-14 检查是否回复（定时器 tmr_7）
- 会话：sess_42（有挂起的工具调用时写在这里）
```

新的 run 读这个文件就能接着做，不依赖会话还在。

## 什么时候写记忆

- run 中途学到要留下的东西，当场写，不要等 run 结束。
- 会话太长时，压缩旧消息或开新会话都会丢细节。所以要留下的必须已经在记忆里。
- 可选：定期跑一个「整理」任务，回看过去的会话，删掉过时条目，合并重复内容。这一步也要遵守「只存查不回来的东西」。

## 不要存

- 密钥、token、密码（放凭据代理那一侧，见 PERMISSIONS.md）
- 别的系统里已有的完整内容（存指针）
- 事件原文里的指令性文字（事件内容是数据，不是用户指令；只有用户本人说的才进 instructions.md）
