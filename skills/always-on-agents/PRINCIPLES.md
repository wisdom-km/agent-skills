# 概念解释：先打比方，再给定义

向人解释时读这个文件。每个概念两层：先日常类比，再正式定义。

## 常驻 agent

- 日常：像值夜班的保安。大部分时间在打盹；门铃响了、闹钟响了才起来，处理完写一笔交接本，再接着睡。看起来「一直有人在」，其实是一段一段地醒。
- 正式：常驻 agent（always-on agent）是有状态、会主动行动的 agent。它在多个会话之间保持上下文，没人看着也能做事。底下的核心循环和普通 agent 一样，区别在外围的五个部件：控制什么时候醒、跨 run 带走什么、结果怎么送到用户手里。

## run 和会话

- 日常：run 是保安起来处理一件事的那一段；会话是这件事的完整处理记录。同一件事可以分几次处理完，记录接着写。
- 正式：run 是一段工作：收到事件，做完任务，保存发生了什么。会话（session）是消息和工具调用的记录。接续旧工作的事件（例如用户回复）接回旧会话；其他事件开新会话。

## 事件收件箱

- 日常：门卫室的登记本。快递、访客、电话，先登记一行，再由值班的那一个人按顺序处理。同一个快递送两次，登记本上只记一次。值班的人突然晕倒了，接班的人翻登记本就知道哪件还没处理。
- 正式：一张持久的事件表、一个写表的入口（通常是 HTTP 接口）、一个读表的 worker。按来源的唯一 ID 去重，记录每个事件的状态。收件箱是唯一真相源；一个收件箱同时只有一个活着的 worker；连着到的事件合成一个 run。

## 定时器：跟进和周期

- 日常：跟进是保安自己贴的便利贴「周三下午再看看 3 号仓库的门」；周期是墙上的排班表「每天早上 8 点巡逻」。便利贴和排班表自己不会叫人，是闹钟按时看一眼，到点了就往登记本里写一行。
- 正式：跟进（follow-up）是 agent 给自己定的一次性截止时间；周期（schedule）是固定节奏的任务，要记录重复规则。定时器存在单独的表里。scheduler 定时扫表：到点的跟进标 done，周期挪到下一次，然后往收件箱写一个事件。

## 记忆

- 日常：交接本。只写下一班查不到的事：「张先生说以后快递放门口」「3 号仓库的门锁坏了，已报修，单号 123」。报修单的全文不抄，只写单号。
- 正式：记忆是持久存储里的一组文件，只存 agent 查不回来的东西，别处已有的只存指针。四类：用户指令、用户笔记、已经告诉过用户的话、每个任务的进度。每次 run 只加载指令和几个索引，细节用到才读。会话压缩或换新都会丢细节，所以要留下的东西在 run 中途就写进记忆。

## 上下文开销和 prompt caching

- 日常：每次上班都要先翻一遍规章和交接本。规章越厚，上班越慢。常翻的那几页可以夹个书签，翻起来快。
- 正式：每个 run 开头都要加载系统提示、工具定义和记忆文件，这是固定开销。保持精简，并用模型服务的 prompt caching 降低重复部分的成本。

## 凭据代理

- 日常：保安不拿各个仓库的钥匙。他要开哪扇门，告诉钥匙房，钥匙房的人核对后去开。保安口袋里没钥匙，就算被骗也交不出钥匙。
- 正式：密钥存在 agent 环境之外。agent 发不带密钥的请求，代理核对白名单后加上真密钥再转发。agent 的环境变量、提示词和记忆里都没有密钥。

## 自动审查（auto mode）

- 日常：保安做普通的事自己决定；要做有风险的事，先过一下值班主管；主管觉得危险就拦下，让他换个办法。真正的大事，等老板来定。
- 正式：对风险较高的动作，先用规则或分类器审查，拦下判为危险的，让 agent 换更安全的做法。最重要的决定仍然留给用户。

## 挂起的工具调用

- 日常：保安遇到要老板签字的事，填一张请示单，放进老板的信箱，然后去处理别的事，不在门口干等。老板签完字，请示单回到登记本上，保安翻出当时的记录接着办。
- 正式：deferred tool call。agent 调用需要批准的工具时，这次调用被挂起，run 结束，会话停在这次调用上存起来。请求展示给用户；用户的答复作为新事件进收件箱，开一个新 run 接回原会话。等待期间 worker 照常处理别的事件。

## 发件箱和三种结局

- 日常：保安每次醒来只有三种收尾：给老板留一张条；没什么事，什么都不留；递一张请示单。好的保安不会每小时留一张「一切正常」。
- 正式：run 的结局只有三种：发消息、什么都不发、挂起工具调用。多数情况一个发送工具就够；要控制节奏或在失败后重试，才建正式的发件箱表和 dispatcher。发多发少用 eval 调；先少说话，再慢慢争取用户的注意力。

## 幂等和去重

- 日常：电梯按钮按十次，电梯也只来一次。
- 正式：同一个操作做多次，结果和做一次一样，叫幂等。收件箱用「来源 + 来源事件 ID」的唯一约束去重；定时器事件用「定时器 ID + 到期时间」；发件箱用 dedupe_key。

## 租约

- 日常：值班牌。谁挂着牌谁值班；牌子到点不续就自动失效，下一个人才能挂上。
- 正式：lease。worker 拿到某个收件箱的租约才能处理它，并定期续租；worker 崩溃后租约过期，别的 worker 才能接手。这样同一收件箱同时只有一个活着的 worker。
