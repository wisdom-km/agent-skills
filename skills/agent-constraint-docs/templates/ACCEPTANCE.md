# 验收记录

- AC：
- 里程碑：
- 精确 head（`git rev-parse HEAD` 的完整输出）：
- 环境（系统 / 硬件；要声称某系统通过，就必须在该系统上跑。模拟器、盒子或其他系统不能代替）：
- 运行方式：
- 真实流程（谁做了什么），或写明「只是样例文字 / CLI 代答」：
- 事实：通过 / 失败 / 被阻断 / 未核实（被阻断写原因。这是事实，不是门禁状态）
- 结果：PASS / FAIL / 未核实（只能三选一。被阻断或未核实不能写 PASS。门禁表里这两类都按 FAIL，不能写成 WAIVED 或 N/A）
- 证据位置（路径或链接）：
- 若复用旧证据：基线 head、为何不用重跑（不能只复制上一份全绿）
- 失败或被阻断时：request_id 和关键日志行（不含密钥、token、授权头、个人数据）：
- 执行人 / 日期：
- 本次是否用到密钥：是 / 否（不写值）
