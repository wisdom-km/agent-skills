# Skills 使用地图

这是**本项目**用过哪些 Skill 的记录，不是功能进度，也不是门禁表。复制到项目根目录，文件名保持 `SKILL_MAP.md`。不要抄回技能库。

- 项目：_（一句话，确认这就是当前要写的根目录）_
- 技能库：_（从本文件出发的相对路径，例如 ../agent-skills/NAVIGATION.md）_
- 记录标记：unknown
- 源更新时间：未知

旁边的 `SKILL_MAP.html` 是给人看的静态路线图，从这一份抄出去。两份的记录标记要相同。不知道整份地图的更新时间就保持 `unknown`，不要编时间。网页写失败就留着旧页，并告诉用户那一页过期。打开网页不会自动改任何文件。

看不清是不是这个项目，或链接会指到别的项目：不要写。

## 规则

- 开工时读技能库 `skills/` 里每个 `SKILL.md` 的目录名，和下面的表对一下。新名字加一行，状态写未核实。不要编造关系，也不要编造用过。
- 下一段工作开始前（不是每条消息）：先看这一段要做什么，再读技能库 NAVIGATION.md「每个 Skill」的「什么时候用」。对得上的，打开那个 SKILL.md 并按它做。对不上就直接做，不要把七个都走一遍。程序一跑就失败、原因还不知道，任何阶段都先打开 `debug-with-logs`。只看懂报错不算用过。没打开的不要写成用过。
- 装上 Skill、读过 `SKILL.md`，都不是用过，也不会自动执行。用过和正在用必须有证据。下一步、有条件、用不上必须有理由。
- 可以同时有多个正在用。可以重复用的 Skill 不会被用完。
- 技能库里以后删掉的名字留在表里，状态改为源已不在。下面的历史不删。
- 改这份文件之前先再读一遍。和上次看到的不一样，就以刚读到的为准，只补这一段。对不上就停下问。不要另做锁文件。
- 一段工作结束时先改这一份，再按技能库 `NAVIGATION.md` 改旁边的 `SKILL_MAP.html`。只写文件，不要为了核对地图去打开浏览器或重画页面。不是每条消息都改。然后说完：用过、正在用、下一步、卡住。没说完就说明收尾不完整。
