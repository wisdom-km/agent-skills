## 10. 运行日志与可观测性

目的：测试或线上出问题时，拿一个请求 ID 就能找到出错的那一层和原因。原型只填前两行。

- 谁读日志、在哪读：
- 看日志的命令（同步到 AGENTS.md 命令表）：`_`
- 输出到哪：stdout / 文件 `_`；由谁收集：
- 保留多久、谁能看：
- core 怎么拿到 logger：只依赖 `Logger` 端口，由装配根注入。core 不 import 具体日志库，不用裸 print。
- 格式：JSON / key=value。字段名全项目统一。
- 请求 ID：在 `_` 生成（或接收上游 trace ID），经 seam → core 用例 → 适配器 → 外部调用一路传。
- 指标、链路追踪：未落地 / 已落地（工具：）

每条日志必带的字段：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| time | 发生时间，带时区 | |
| level | 见级别表 | |
| event | 固定的事件名，snake_case | `order_submit_failed` |
| request_id | 关联 ID，入口生成，跨层传递 | |
| module | 切片或适配器名 | |
| outcome / error | 结果，或错误原因 | |
| duration_ms | 耗时，外部调用必带 | |

级别含义：

| 级别 | 什么时候用 | 看到后做什么 |
| --- | --- | --- |
| ERROR | 操作失败，结果不对 | 要有人查 |
| WARN | 没失败但不正常：重试成功、降级、输入被拒 | 看趋势 |
| INFO | 发生了一件该记的事：用户操作、启动停止、配置变化 | 不用动 |
| DEBUG | 诊断细节 | 默认关，排查时打开 |

要记的事件：

| 事件 | 级别 | 字段 | 在哪一层记 | 负责切片 |
| --- | --- | --- | --- | --- |
| `request_received` / `request_completed` | INFO | request_id, operation, outcome, duration_ms | 入口 / seam | |
| `<adapter>_call_failed` | ERROR | request_id, target, error, duration_ms | 适配器 | |
| | | | | |

绝不记（对应 RULES N-01、L-05）：密码、token、API key、session 值、连接串、加密密钥、银行卡、个人敏感数据、整段请求体或响应体。外部输入写进日志前去掉换行符。

排查时怎么读：先按 request_id 过滤；找第一条 ERROR；看它前面最近的外部调用。日志找不到原因时，修复里要补上缺的那条日志，并更新上面的事件表。
